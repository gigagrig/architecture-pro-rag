# Как проверить бота в Telegram

## Перед проверкой

Бот: [@StarWarsRagExampleBot](https://t.me/StarWarsRagExampleBot).

Владелец должен запустить API и Telegram-процесс по [инструкции запуска](task4_rag_bot.md). Пока процессы остановлены или LLM не настроена, бот не сможет отвечать на вопросы. Проверяющему не нужны Python, API-ключ или токен бота: достаточно Telegram.

## Начало работы

1. Перейдите по ссылке на бота и нажмите **Запустить / Start**.
2. Отправьте `/start`. Должны появиться приветствие, примеры вопросов и команды.
3. Отправьте `/help`. Должна появиться справка.
4. Отправьте `/health`. Ожидается сообщение о работающем API, 189 фрагментах индекса и выбранной модели. Эта команда проверяет API и индекс; генерацию проверяют следующие вопросы.

Проверяйте в личном чате с ботом: сообщения в группах не обрабатываются. Каждый вопрос задавайте отдельным сообщением и дожидайтесь ответа. На CPU генерация может занять заметное время.

## Вопросы, на которые есть ответ

Имена лучше копировать без изменений. База англоязычная, но вопросы можно задавать по-русски.

| Сообщение боту | Что должно быть в ответе |
|---|---|
| Кто отец Kael Ardyn? | Xarn Velgor |
| Кто сестра-близнец Kael Ardyn? | Lyra Voss |
| На какой планете вырос Kael Ardyn? | Draxos |
| Какие объекты способен уничтожать Void Core? | Планету |
| Что за оружие arcblade? | Энергетический клинок / меч |

У полезного ответа должны быть краткое обоснование и раздел «Источники» с названием документа, идентификатором фрагмента и цитатой. Формулировки могут меняться. Сверяйте смысл, а не полное совпадение текста. Цитаты могут оставаться на английском.

Для проверки переформулировки отправьте: `Как зовут отца Kael Ardyn?` Смысл ответа должен сохраниться. Уточнения вроде «А его сестра?» не подходят: история диалога не передаётся модели, имя нужно повторить.

## Вопросы без ответа в базе

Отправьте по очереди:

1. `Какой любимый десерт Kael Ardyn?`
2. `Какой пароль от Wi-Fi в офисе QuantumForge?`

Ожидается: «Я не знаю. В базе знаний недостаточно информации для ответа». Бот не должен придумывать десерт или пароль, добавлять источники к отказу либо выдавать сообщение о недоступности API вместо честного отказа.

Это ожидаемые результаты проверки, а не запись уже состоявшегося разговора.

## Проверка неудобных ситуаций

- Отправьте фотографию или голосовое сообщение. Бот должен попросить задать вопрос текстом.
- Отправьте `/unknown`. Бот должен предложить `/help`.
- Если владелец временно остановит API, вопрос должен получить сообщение о технической ошибке. После запуска API бот должен снова отвечать без перезапуска Telegram-процесса.
- Если задан список разрешённых пользователей, посторонний пользователь должен получить сообщение об ограничении доступа.

## Как сохранить результат

Сделайте скриншоты пяти полезных ответов и двух отказов. На каждом должны быть видны вопрос, ответ и имя бота; длинный ответ можно сохранить несколькими скриншотами. Запишите дату проверки и модель из `/health`. Это примеры для задания 4; дополнительные проверки и десять скриншотов из общего задания относятся к следующей демонстрации.

Если что-то не работает, передайте владельцу текст вопроса и сообщения об ошибке. Не пересылайте токен или содержимое `.env`.

## Если бот молчит

Проверьте, что открыт именно личный чат с указанным ботом и нажата кнопка Start. Попросите владельца проверить, что запущены оба процесса, компьютер не спит и доступен интернет. Ошибка `409` в терминале владельца обычно означает второй процесс polling или конфликт с webhook; должен работать только один экземпляр бота.
