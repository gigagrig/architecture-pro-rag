## Задание 4. Реализация RAG-бота с техниками промптинга

### Выполнено

- Реализован модуль RAG: загрузка FAISS-индекса из 189 фрагментов, E5-энкодер, поиск, few-shot примеры, краткое обоснование и проверка ID источников и непустых цитат.
- Подключена Yandex Alice AI LLM Flash: `gpt://b1g2bu1h99h8aoj25qf5/aliceai-llm-flash/latest`. Генерация выполняется через Chat Completions со структурированным JSON, эмбеддинги вычисляются локально.
- Работают FastAPI (`POST /ask`, `GET /health`, `/docs`) и Telegram-бот [@StarWarsRagExampleBot](https://t.me/StarWarsRagExampleBot), использующий тот же API.
- Настройки сведены к одному `docker-compose.yml` с двумя сервисами — API и ботом. Ключ Yandex и токен Telegram подключаются через отдельные secrets, исключены из Git и образа.
- Выполнены 23 автоматических теста API, RAG, HTTP-клиента модели и обработчика Telegram с подменой внешних сервисов. Все тесты прошли.
- Приёмка через реальный API: 7 из 7 сценариев прошли — пять ответов с источниками и два корректных отказа.
- Подготовлены [реальные диалоги через API](task4_dialogues.md), [машиночитаемый отчёт](task4_api_results.json) и [инструкция ручной проверки Telegram](TELEGRAM_TESTING.md).
- Docker-образ пересобран, API и Telegram polling запущены. Переписка пользователя в Telegram не считывалась и не выдаётся за автоматическую проверку.

### Проблемы и решения

Модель иногда перефразировала цитаты, из-за чего корректный ответ заменялся на «Я не знаю». По решению пользователя проверка дословного совпадения и повторная генерация удалены. Сохранены проверка принадлежности chunk_id текущим результатам поиска и проверка непустого текста цитаты.

При последующей проверке модель вернула цитату длиннее ограничения контракта. Запрос переведён с произвольного JSON на схему `GeneratedAnswer`; ограничены инструкции по длине и содержанию ответа. Сетевые ошибки и некорректный формат остаются технической ошибкой HTTP 503, а не маскируются под отсутствие знаний.

Проверка семи вопросов является учебной приёмкой, а не гарантией качества на произвольных запросах. Цитаты возвращаются как сформулированы моделью; их точность и соответствие утверждениям автоматически не проверяются. Демонстрация prompt injection относится к заданию 5.

## Задание 6. Автоматическое ежедневное обновление базы знаний

### Выполнено

- Реализован скрипт обнаружения новых, изменённых и удалённых документов по SHA-256 с переиспользованием неизменённых эмбеддингов.
- Добавлены публикация согласованных версий FAISS, блокировка одновременных обновлений и подхват версии работающим API.
- Настроен и запущен Docker-сервис ежедневного обновления в 06:00 по Москве с повтором после ошибки через пять минут.
- Проверены первый запуск планировщика, наличие следующего запуска в журнале и здоровое состояние API.
- На временной копии базы с настоящей E5-моделью проверены добавление документа, поиск, изменение, удаление и отсутствие изменений. Проверен подхват индекса без перезапуска Retriever.
- Общий набор: 29 тестов прошли; интеграционный тест, отключённый по умолчанию, успешно выполнен отдельно вместе с тестом жизненного цикла.
- Подготовлены инструкция, диаграмма PlantUML, изображение диаграммы и журналы проверки; обновлены README и шаблон решений.

### Проблемы и решения

Для управления Docker и выполнения тестов API потребовался разрешённый запуск вне песочницы. PlantUML запущен в headless-режиме из-за отсутствия доступного X11. Нерешённых проблем, мешающих выполнению задания, нет. Планировщик проверен запуском при старте; ожидание календарного запуска до 06:00 не выполнялось.
